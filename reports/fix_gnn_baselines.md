# Fix: graph-neural-network baselines (GCN seeds, GCN learning rate, GraphSAGE, Mowst, GAT)

Date: 23 November 2026. Issue source: reports/independent_review.md, paragraph on baselines and recommendation 3.

## What the review asked for and what was done

The review noted that the GCN baseline had been run with only three seeds (42, 1, 7), used a fixed learning rate of 1e-2 with no search, existed in two inconsistent code paths (an unused path in run_experiments.py with lr 1e-3 and 600 epochs, and experiments/run_gcn.py, which actually produced the results, with lr 1e-2, at most 400 epochs and patience 60), and that GraphSAGE, GAT and Mowst, the closest prior art, had not been run. Within a compute budget of about 90 CPU-minutes I completed the GCN to five seeds under the configuration that produced the existing results, ran a validation-only learning-rate check, added a GraphSAGE baseline with five seeds and a Mowst-style baseline with three seeds, and measured the per-epoch cost of a GAT. I did not train the GAT. No test-period label or prediction was used for any choice. Test metrics were computed once, by experiments/gnn_v2_summary.py, after every prediction file had been written.

All models use the 165 AF features (f1 to f165), standardised with the mean and standard deviation of the training nodes, and the loaders in src/preprocessing.py. All follow the temporal protocol of the revision spec. Each OOT run trains on labelled steps 1 to 29 and early-stops on validation PR-AUC over labelled steps 30 to 34, checked every 10 epochs with patience 60 and a cap of 400 epochs. That run's predictions on block 30 to 34 are stored as `oot`. Each model is then refitted on labelled steps 1 to 34 for the selected number of epochs, and its predictions on steps 35 to 49 are stored as `test`. Every model uses class-weighted cross-entropy (weights 0.3 and 0.7), Adam with weight decay 5e-4, hidden width 100, dropout 0.3 and full-batch training on the symmetrised transaction graph. Elliptic has no cross-step edges, so test nodes never exchange messages with training nodes. For these neural baselines, block 30 to 34 serves both for early stopping and for the Platt/threshold fit, as it already did for the original GCN. Every GNN number below is therefore, if anything, optimistic for the GNNs.

## Code and commands

The new code is baselines/gnn_v2.py (GraphSAGE, the Mowst mixture and a GAT layer used only for timing) and experiments/run_gnn_v2.py (the runner, which computes no test metric). The test summary script is experiments/gnn_v2_summary.py. The GCN seeds reuse the unmodified baselines/gcn.py with exactly the arguments of experiments/run_gcn.py. Each job was run in the background under the shared lock, as `nohup flock /tmp/cpu.lock python3 experiments/run_gnn_v2.py <cmd> <seeds>`, in this order: `gcn_seeds 123 2024`, `sage 42`, `gat_time`, `mowst 42`, `gcn_lrcheck`, `sage 1 7`, `mowst 1 7`, `sage 123 2024`. The summary was then produced by `flock /tmp/cpu.lock python3 experiments/gnn_v2_summary.py`. The log is logs/gnn_v2_chain.log (plus logs/gnn_v2_gcn.log for the two GCN seeds).

The result files are as follows. The new prediction files are results/preds/GCN_seed123.npz, GCN_seed2024.npz, GraphSAGE_seed{42,1,7,123,2024}.npz and Mowst_seed{42,1,7}.npz; the existing GCN_seed{42,1,7}.npz were not touched. Per-run times, selected epochs and validation PR-AUC are in results/runtime_gnn_v2.csv. Per-run training details are in results/gnn_v2_{GraphSAGE,Mowst}_seed*_info.json, including validation curves and, for Mowst, the turn log and confidence statistics. The learning-rate check is in results/gnn_v2_gcn_lrcheck.json and the GAT timing in results/gnn_v2_gat_timing.json. The final metrics are in results/gnn_v2_summary.csv (mean and s.d. over seeds) and results/gnn_v2_per_seed.csv.

## 1. GCN completed to five seeds

Seeds 123 and 2024 were run with the configuration of experiments/run_gcn.py, so the three existing seeds remain valid and all five seeds share one protocol. Early stopping selected 301 and 351 epochs, compared with 211, 251 and 241 for seeds 42, 1 and 7. Validation PR-AUC on block 30 to 34 was 0.8863 and 0.8939, against 0.8739, 0.8779 and 0.8772 for the existing seeds. Over all five seeds the test PR-AUC is 0.6431 ± 0.0152 and F1 is 0.6319 ± 0.0201, after Platt scaling and an F1-optimal threshold both fitted on block 30 to 34. The three-seed values in the current results/metrics_summary.csv are 0.6480 and 0.6395, so adding two seeds changes the GCN by less than one seed s.d. This resolves the seed-count discrepancy: the manuscript statement that neural models were run with seeds 42, 1, 7, 123 and 2024 is now true for the GCN. The unused lr 1e-3 GCN path in run_experiments.py is not mine to edit. The lead should state in the manuscript, or in a code comment, that experiments/run_gcn.py (and this runner) is the only GCN path that produced results.

## 2. Validation-only learning-rate check for the GCN

For seed 42, lr 1e-2 (the existing run, at most 400 epochs) gives validation PR-AUC 0.8739. A fresh run at lr 1e-3, with the 600-epoch cap of the other code path and patience 60, gives 0.8116. Because 1e-3 is not better on validation, and is in fact clearly worse, the main results stay at lr 1e-2 and no seeds were rerun. One caveat applies: at lr 1e-3 the best validation epoch was 591 of 600, so that run had not converged within its budget. The check shows that lr 1e-3 is worse at the budget actually used in either code path, not that it would be worse with unlimited epochs. No depth grid was run. The review's request for a learning-rate and depth grid is therefore only partly met, by a two-point learning-rate check on one seed.

## 3. GraphSAGE

The model follows Hamilton, Ying and Leskovec (2017), "Inductive Representation Learning on Large Graphs", NeurIPS 2017 (arXiv:1706.02216). It is a two-layer GraphSAGE with mean aggregation over the symmetrised one-hop neighbourhood, separate self and neighbour weight matrices in each layer, hidden width 100, ReLU and dropout 0.3. It uses full neighbourhoods rather than sampled ones, has no L2 normalisation of the embeddings, and is implemented in plain PyTorch with sparse matrices. Because the input features are fixed, the layer-1 neighbour mean of the inputs is computed once; this is mathematically identical to recomputing it every epoch. All five seeds were run. Selected epochs were 141, 381, 231, 151 and 171 for seeds 42, 1, 7, 123 and 2024. Validation PR-AUC was 0.9499 ± 0.0039, clearly above the GCN's 0.8818 ± 0.0082. Test PR-AUC is 0.6880 ± 0.0169, F1 0.6691 ± 0.0051, ROC-AUC 0.9060 ± 0.0046, F1 before step 43 is 0.7585 and F1 from step 43 on is 0.0132. GraphSAGE is therefore the strongest of the end-to-end message-passing baselines here, and it is 0.045 PR-AUC above the GCN. It still remains far below the feature-only tree models in results/metrics_summary.csv (LGBM-AF PR-AUC 0.8016, F1 0.8013). Like every other model, it collapses after step 43.

## 4. Mowst-style baseline

The method was checked against the paper and the released code before coding. The paper is Zeng, Lyu, Hu, Xia and Luo, "Mixture of Weak & Strong Experts on Graphs", ICLR 2024 (arXiv:2311.05185; ICLR 2024 poster 17490; code github.com/facebookresearch/mowst-gnn). The paper (Section 2.2) defines the confidence as C = G∘D, where D is a dispersion of the weak expert's softmax p (variance, D(p) = Σᵢ(pᵢ − 1/n)², or negative entropy) and G is non-decreasing with G(0) = 0. G can be fixed or learnable. The training loss (Eq. 1) is the confidence-weighted average C(p_v)L(p_v, y_v) + (1 − C(p_v))L(p'_v, y_v). Training proceeds "in turn" (Algorithm 2): the MLP is updated with the GNN fixed, then the GNN with the MLP fixed, and the two steps repeat. Inference (Algorithm 1) samples the MLP's prediction with probability C(p_v) and otherwise uses the GNN's. In the released code, compute_confidence() normalises the softmax variance by its maximum, and the confidence is raised to a power `alpha`.

I implemented the simplest variant. The weak expert is a two-layer MLP on AF (hidden 100, dropout 0.3) and the strong expert is the GraphSAGE of Section 3. The confidence is the normalised variance of the MLP softmax, which for two classes equals (p₁ − p₀)², with fixed G(x) = x (alpha = 1). The loss is Eq. (1) with the class-weighted cross-entropy used by all GNN baselines. Training alternates in turns with no pretraining, which is the code's default `submethod=none`, starting with the MLP.

The following simplifications were made for the 2-core CPU budget and the temporal protocol. Each turn runs at most 150 epochs and is early-stopped on validation PR-AUC of the mixture score, evaluated every 10 epochs with patience 40; the code uses up to 20000 epochs per turn with patience 100 on validation loss. At most 3 rounds are run, and training stops after the first round with no new best validation PR-AUC; the code allows big_patience 10. The learning rate (1e-2) and weight decay were not tuned; the paper searches lr over {0.1, 0.01, 0.001}. Ranking metrics need a continuous score, so the score is the expectation of the sampling rule, C·p + (1 − C)·p'. This is the Mowst* weighted combination applied to experts trained with the Mowst loss; I did not train Mowst* (Eq. 3) separately. During the MLP's turn, gradients flow through C, as Eq. (1) implies. In the released repository's variance path, compute_confidence is decorated with @torch.no_grad(), so that code would not pass gradients through C; I followed the paper. The refit on steps 1 to 34 replays the turn schedule selected out of time. For example, for seed 42 the schedule was MLP 130 epochs, then GNN 50, then MLP 10. Adam moments are carried across turns, which is a minor difference from the OOT run, where each turn's best state was restored after a few extra epochs.

Three seeds were run (42, 1, 7). Seeds 123 and 2024 were not run for lack of budget: each Mowst seed cost 9 to 11 minutes. Validation PR-AUC was 0.9118 ± 0.0054, between the GCN and GraphSAGE. Test PR-AUC is 0.6502 ± 0.0213, F1 0.6511 ± 0.0294, ROC-AUC 0.9035 ± 0.0052, F1 before step 43 is 0.7328 and F1 from step 43 on is 0.0217. The MLP dominated the mixture. On the validation block the mean confidence was 0.86 for seed 42, and 89% of validation nodes had C > 0.5, so the GraphSAGE expert decided only a minority of nodes. This Mowst-style mixture is worse than GraphSAGE alone, on both validation and test. Even the closest per-node weak/strong-expert prior art, run in its simplest form, does not approach the feature-only tree models on Elliptic. This is a statement about an untuned, simplified Mowst, not about the best achievable Mowst.

## 5. GAT

A two-layer GAT (4 heads × 25 hidden in layer 1, one head in the output layer, self-loops, edge-wise softmax with index_add) was implemented only to measure cost. Over 672,479 directed edges including self-loops, one full-batch training epoch took a median of 1.92 s (2.73, 1.91 and 1.92 s over three epochs). That is roughly twice the GCN's cost per epoch. Under the same protocol (up to 400 OOT epochs plus a refit of comparable length), one seed would cost about 15 to 25 minutes uncontended. When the timing was taken, about 82 of the 90 budget minutes were already committed to the GCN, GraphSAGE and Mowst runs, so no GAT seed was trained. GAT is therefore not run. Its omission is a budget decision, not a technical impossibility on this machine.

## Compute spent

The total recorded in results/runtime_gnn_v2.csv is 89.8 minutes of wall time while holding the lock: GCN 18.6 minutes (two seeds), the lr check 8.4, GraphSAGE 31.5 (five seeds) and Mowst 31.3 (three seeds). The GAT timing added about one more minute. Wall-clock time was much longer because of queueing on the shared lock.

## Verdict

The following points are resolved. The GCN now has the five stated seeds under a single configuration that matches the existing results. The learning-rate question was answered on validation only, and lr 1e-2 was kept because lr 1e-3 was worse. GraphSAGE (five seeds) and a documented Mowst-style baseline (three seeds) have been added in the standard npz format, so experiments/statistical_tests.py will pick them up automatically. Three things remain partly open. There is no depth grid for the GCN, only a two-point learning-rate check on one seed. Mowst has three seeds rather than five and is a simplified, untuned variant, with every simplification listed above. GAT, EvolveGCN and Label-GCN were not run; for GAT the reason is the measured cost of 1.92 s per epoch against the remaining budget. The substantive conclusion is unchanged and now rests on stronger baselines: the best end-to-end GNN here (GraphSAGE, test PR-AUC 0.688) remains far below feature-only LightGBM (0.802), and no GNN escapes the post-step-43 collapse.

## Seeds 123 and 2024 added (23 November 2026, addendum)

After the sections above were written, Mowst seeds 123 and 2024 were run to bring the Mowst-style baseline to the five seeds of the protocol. Neither baselines/gnn_v2.py nor experiments/run_gnn_v2.py was changed: both files carry modification times earlier than the first Mowst run. No hyperparameter was changed, and the code path was the same one that produced Mowst_seed{42,1,7}.npz. The command was `nohup flock /tmp/cpu.lock python3 experiments/run_gnn_v2.py mowst 123 2024`, and its log is logs/gnn_v2_mowst_extra.log. The selected turn schedules were MLP 140, GNN 40, MLP 40, GNN 10 for seed 123 and MLP 150, GNN 140, MLP 70, GNN 130 for seed 2024. Validation PR-AUC on block 30 to 34 was 0.9132 and 0.9231. Wall time under the lock was 7.9 and 14.6 minutes, which adds 22.5 minutes to the compute recorded above.
